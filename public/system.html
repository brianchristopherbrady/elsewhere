Architecture

The structural system owns data, state, control semantics, and business logic. The design lens owns typography, image treatment, geometry, and composition. Color mode independently maps surfaces, text, actions, focus, warnings, and map treatments.

Root data-lens and data-mode select six mappings without changing component keys. Saved places and planned stops remain independent. Theme preferences, date, stops, and saved places persist locally; filter and view preferences remain session state.

Field Journal
Newsreader headings, DM Sans body, IBM Plex Mono numerals, printed-photo framing, low elevation, and botanical accents.
Nocturne
Manrope typography, image-led cards, contrasting surfaces and a luminous map route. The itinerary remains a vertical sequence.
Civic Modern
Public Sans, compact rows when space permits, square geometry, and blue light-mode or lime dark-mode actions.

Token Layers

src/tokens.css is the runtime source of truth. Foundations cover rem-based spacing/type, sizing, borders, focus, opacity, layers and measures. Existing lens fonts, radius, shadow and duration remain shared. Semantic colors retain their established names, including --canvas, --surface, --text, --muted, --accent, --danger and --focus.

--control-border provides stronger input/action boundaries than quiet structural --border. Selected controls use --selected-border as well as pressed semantics. Photo overlay colors remain legible independently of page mode. Component decisions include planner width, minimum card width and compact control size.

The high-contrast preview overrides all six palettes and native form color-scheme. OS reduced motion, increased contrast and forced colors remain separate preferences. There is no additional density mode or token build dependency; another consumer must justify token serialization.

Component Contracts

IconButton and Forms

IconButton requires a label and icon children, accepts native button props and an additive className, and supplies a matching accessible name and native title tooltip. Use aria-pressed for toggles and disabled for unavailable commands. Targets are at least 36px at the default font size, or 44px for coarse pointers. Native labeled fields, selects, checkboxes and textareas retain their platform keyboard behavior. A placeholder is never the only label. Maturity: shared with browser coverage.

PlaceCard / Photo

Existing props: place, index, saved, planned, and save/add/select callbacks. Saved and planned are independent. Image and title open the same preview. Photos have stable dimensions and a named fallback; drag is an enhancement with an explicit Add alternative. Maturity: product component with six-lens and expanded-content tests.

DayPlanner / StopItem / Balance

Receives unique stops with minute-based start times and durations. Reordering preserves chosen times and surfaces conflicts. Edit, remove, earlier/later and drag commands remain available; boundary controls are disabled. Removal focuses the planner heading; undo restores the itinerary. Condensed mode is a summary, with Expand restoring editing. Five labeled native meters show editorial balance estimates, not scientific recommendations. Maturity: domain and browser tested.

DiscoveryMap

Leaflet controls zoom, pan, resizing, clustered keyboard markers and attribution. Lines connect Seattle stops using approximate coordinates and walking estimates, not street routing. The equivalent travel list remains readable without tiles. Tile errors offer retry. OpenStreetMap is an online enhancement; do not prefetch public tiles and choose an appropriate provider before high-volume deployment.

Modal

Props remain title, open, onClose, children and className. Native dialog.showModal makes the background inert. Initial focus is the close button; Tab/Shift+Tab wrap. Escape, close and outside clicks dismiss; the browser restores trigger focus. Related-place previews update the same dialog. Constrained-height dialogs scroll internally. Do not nest modal workflows. Maturity: shared with interaction and narrow visual coverage.

LiveEvents / System Inspector

The live calendar keeps loading, stale, expired, error and empty states and reuses IconButton for refresh. Filters remain native labeled controls. Inspector reports computed tokens and first mounted component dimensions; its solid text/canvas contrast is not a full accessibility evaluation. High-contrast palette preview is not OS forced-colors testing. Both retain their existing product APIs.

Responsive Rules

The shell pairs flexible discovery with a 21rem planner. At 1150px the gutter and planner narrow to preserve working space. At 850px the existing Explore / My day / Day map controls switch between single-column surfaces. At 520px theme controls get separate rows and detail facts stack. No essential control or distance label is hidden to make content fit.

Discovery uses an intrinsic grid with 16rem minimum cards. Below a 30rem discovery container, Civic rows become image-above-content cards and the decorative stamp disappears. Calendar timestamp/content rows stack below a 38rem event container. These component decisions follow available space, not device names.

Grid/flex children containing long text or selects can shrink. Forms and actions wrap. Typography uses rem roles, never viewport units. Images use aspect ratios, while text-bearing areas grow naturally. Maps retain explicit 360/400px minimum heights and ResizeObserver-driven Leaflet resizing. Dialogs use dynamic viewport bounds. Logical properties and safe-area padding support structural RTL, not a completed translation.

Focus scrolling is immediate: global smooth scrolling can move dnd-kit geometry between keyboard movement and drop. Keep DOM and keyboard order consistent with the visual sequence.

Accessibility and Evidence

The target is usable WCAG 2.2 AA-oriented interaction, not an unsupported conformance claim. Native labels, datalist autocomplete, checkboxes, selects, meters, semantic sections, dialog focus, status feedback, and explicit drag alternatives are used. Themes expose selected state through aria-pressed, not only color. Motion responds to OS preferences and inspector override. Forced colors retain control boundaries.

Run npm test for deterministic domain checks, npm run test:e2e for Chromium interaction and axe scans, and npm run build for TypeScript and production bundling. Browser viewport tests are not physical-device or actual browser-zoom evidence. See the repository verification report for exactly what was tested.

Implementation guidance: MDN native dialog, dnd-kit sortable controls, WCAG 2.2, OpenStreetMap tile policy.

Contributing and Limits

Propose a consuming workflow and measurable failure first. Add tokens for repeated decisions, not every declaration. Validate a representative workflow before migrating another. Run unit, browser and build gates; no separate lint/formatter script is configured. Review screenshot changes before updating the Windows/Chromium baselines.

Release source, contracts and tests together. This is a single-app system, not a versioned package. Public APIs remain compatible; no migration adapters are required. Removed patterns include split-view overrides, absolute mobile mode controls and pixel-shrinking mobile labels. Deprecations need a replacement and removal milestone after all consumers migrate. Full migration map, examples and release criteria are in the repository's docs/design-system-upgrade.md.

Live events uses the official City calendar through a Node endpoint with a 15-minute cache. Failures retain visibly stale listings for at most 24 hours. It is not live ticket inventory or comprehensive event coverage; listings link to their official source and are not planner stops. Production needs the Node server.

Discover uses Seattle places and the dated SAM tour reviewed September 17, 2026. Unknown hours/access remain unverified. Costs, moods, durations and walks are estimates. Photography is labeled illustration, not venue imagery. Loaded-app planning works offline, but cold-start offline is not supported. No analytics, authentication or bookings are present.

Actual 200%/400% browser zoom, NVDA/JAWS/VoiceOver, physical touch hardware and Firefox/Safari remain external verification gates. Viewport resizing, root text enlargement, axe and media emulation are not substitutes and do not establish full WCAG conformance.
